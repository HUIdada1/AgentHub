## 项目归档：同一 Git 地址的项目自动归类同名，名称不再是一串机器码

- 修复「项目名称没获取到」：卡片名此前会被写成 slug 机器串（如 `huidada1--agenthub`）甚至显示为空。现在按 **Git 远程地址归类**——同一仓库的多张项目卡自动统一显示名，名字依次取「用户手动改的名 → 远程仓库名 / 已登记的真名 → slug 反解出的仓库名」，机器串不再出现在名称栏
- 归类只统一显示名与元数据（远程列表、完整 git 地址），**不合并卡片、不搬动任何记忆文件**，卡片数量与记忆归属完全不变；想真正合并可用卡片菜单「合并到…」
- 项目卡新增完整 git 地址（如 `github.com/HUIdada1/AgentHub`）：启动自愈与每 6 小时的索引扫描会从已关联的本地目录补齐，无远程的卡片也会从同仓库的卡片继承
- 写入侧的名字裁决：Agent 传 slug、导入传目录名都不再把已登记的真名覆盖成机器串；归档页「重命名项目」为人工命名，优先级最高，自动归类永不覆盖

## 记忆浏览：标题/项目列限宽，悬停看 git 地址

- 标题列限宽 380px、项目列限宽 180px，超长省略号（此前长标题会把整行撑到横向滚动，一屏看不到几列）
- 项目列显示归类后的项目名；**鼠标悬停显示该项目的 git 地址**（完整地址优先，其次远程列表，最后按 slug 反解）

## 记忆浏览 · 回收站：五类异常记忆可开关自动删除；回收站默认 30 天

- 新增五个默认**关闭**的开关（记忆浏览 → 回收站页同屏开关，配置页「清理」分组亦有）：**失效记忆**（被新记忆取代 / 有效期已过）、**不存在记忆**（索引还在、文件已丢）、**报错记忆**（文件在但读不出来）、**冲突记忆**（同步冲突未裁决）、**无效记忆**（空壳文件、进不了索引的残骸）
- 删除一律先进回收站、保留期内可恢复；「不存在」类只清索引行（没有内容可入站）；每日记录类多节文件在冲突清理时保守跳过，不做连带删除
- 新增「异常记忆清理」自动化任务（每天 04:00，零 token 消耗）：按上面开关执行清理，并把**回收站到期文件从磁盘彻底删除**——回收站默认保留期由 90 天改为 **30 天**（此前自定义过保留期的用户不受影响）
- 五个开关全关时任务只清回收站、不做全库扫描（零额外成本）；任务可在「自动化」页「立即执行」，回收站页也有「立即清理一次」
- 提醒：删除会随记忆同步传播到其他设备（这是同步的既有语义），开启自动清理前请确认

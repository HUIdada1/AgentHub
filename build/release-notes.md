# v2.0.4 更新说明

> **【最新架构测试版 · 请自行判断是否更新】**
> 本版延续「模型增强执行引擎外置为插件」的架构测试线，新增跨渠道积分优先选号，并给插件会话与模型目录的热路径减负，**请自行判断是否更新**；稳定版发布时将另行提供完整的更新说明。
> 建议配合 `AgentHub_skill` **v0.2.7** 插件使用（与本版同期发布）。

## 本地网关：跨渠道「积分优先」选号

- 新增全局路由策略 **积分优先（credit-first）** 与模型组策略 **积分优先（credit）**：把账号提到第一决策单位，跨渠道按「免费 → 快到期 → 晚到期 → 永久 / 未知」挑出唯一账号，再连同渠道与真实模型一起钉给执行器，本轮不再换号。
- 资格判定仍全部走号池既有账号计划（在线、凭据、余额、过期、冷却、并发），选号器只做排序，不复制第二套规则；选号与执行之间的毫秒级窗口里若该号已不可用，执行器自动回落到原排序的首个可用账号。
- 显式渠道指定（模型改名覆盖 / 渠道锁定）不会被绕过；模型组的成员顺序在「同档同到期」时兜底；不同渠道的积分数额不互相折算，与账号调度页口径一致。
- 日志页的每次尝试新增「实际使用的账号」（本机 UUID 前 8 位），可直接核对「为什么走这个号」。
- 新增只读预览入口 `localgw_credit_route_preview`：输入对外模型名，返回候选顺序、积分档位与不可用原因，不改号池状态；本期不提供界面，供排障与后续 UI 使用。

## 性能：插件会话快照与目录索引

- 插件会话查询处在转发链路热路径，原实现每次都全目录扫描并逐份校验签名，单次流式请求可触发数百次同步 IO 阻塞主进程。现改为「状态变更点显式失效 + 1 秒兜底」的会话快照，并返回防御性拷贝，避免调用方原地排序污染缓存。
- 模型目录的历史绑定从「每个模型重扫一遍历史」改为一次展平建索引，目录列表开销不再随模型数线性放大。
- 「可用账号优先」策略的渠道摘要改为一次算齐再排序，避免比较器里重复查库。

## 修复与自测

- 已定账号贯通标准执行器与插件执行器两条链路，行为一致；日志与操作记录落实际账号 id。
- 新增积分选号与积分路由两个自测脚本，模型组自测同步覆盖 credit 策略。

# v2.0.3 更新说明

> **【最新架构测试版 · 请自行判断是否更新】**
> 本版延续「模型增强执行引擎外置为插件」的架构测试线，新增本地网关的模型组与消耗倍率、插件安装即用，并修正 Qoder / Trae 模型清单与积分显示，**请自行判断是否更新**；稳定版发布时将另行提供完整的更新说明。

## 本地网关：模型组（一个对外名，多个渠道模型）

- 新增「模型组」：给一组「渠道 + 实际模型」起一个对外名（例如 `free`），客户端只请求这个名字，转发层按组策略挑一个成员执行。
- 两种策略：**顺序优先**（按成员顺序取第一个可用，失败自动换下一个）、**轮询**（在可用成员间轮流，把请求摊到多个渠道 / 账号）。
- 成员级故障转移：同一渠道挂多个模型时，某个模型不可用只判死该成员，不会连带整条渠道；成员全部不可用时返回 503 并说明原因，不会悄悄换回同名的单渠道模型。
- 组名大小写不敏感（`Free` / `free` 视为同一个组）；与改名覆盖、自定义模型、别名重名会被拒绝，避免两套规则静默抢同一个名字。
- 模型页可直接增删组成员、调整成员顺序、改组名。

## 本地网关：模型消耗倍率

- 上游目录不一定给倍率（Trae 就没有），新增按模型手填倍率，用于展示与比价；用户手填优先于目录声明。
- `0` 是合法倍率（免费档），与「未知（—）」分开显示。

## 外置插件：装完即用

- 全新安装后按签名清单自动授权（只给必需权限与已声明渠道）、自动启用并启动，并把声明渠道固定到该插件，等价于手动点一次「全部固定」。
- 三道避让：来源当前不可用、渠道已绑定其它来源、渠道被自定义提供商占用时都不写绑定。更新插件仍保持用户原有的启停选择。

## 模型清单与积分：对齐官方客户端

- **Qoder / 千问办公**：对外模型名改用官方客户端展示名（去空白），发往上游仍用内部 key；静态兜底补齐倍率、能力与上下文长度，未拉目录时界面也能正确显示。
- **Trae**：改用 `batch_get_detail_param` 一次拉全 7 个聊天通道的目录（旧的单通道查询会漏掉其它通道新增的模型），并剔除内部 subagent 与租户占位模板。
- **积分显示**：修正「明明有积分却一直显示 0」——Loomy 的逐钱包明细与 CodeArts 的 `available` 字段口径不同，现在统一归一为数字 `credits`；两份账都读不到时保留上一次有效读数，不再把故障回合清成 0。

## 记忆中枢

- token 预算改为按完整行边界截断，并返回 `truncated` / `totalTokens` / `omittedTokens` / `omittedLines`，调用方能判断内容是否被丢弃。
- `memory_core` 支持按次传入 `maxTokens`（200–4000）；配置项 `agents.coreMaxTokens` 上限从 2000 放宽到 4000。

# v1.99.0 更新说明

## 本地网关 · 模型目录恢复「渠道锁定」列（v1.82.2「渠道覆盖」回归）

- **问题**：1.91 起本地网关接替旧版「反代网关」，但页面上只剩下「改名覆盖」（对外名 → 某渠道的**另一个**实际模型名），v1.82.2 那个「只换渠道、不改模型名」的渠道覆盖没有跟过来。想「让 gpt-4o 固定走 A 家、上游仍叫 gpt-4o」只能去写改名覆盖，等于被逼着多填一个容易写错的上游模型名。
- **模型目录页新增「渠道锁定」列**：下拉即改即存，选项 =「自动（按路由策略）」+ 该模型真实存在的渠道。只决定「走哪个渠道」，发给上游的模型名一个字不动。
- **分工写清楚**：Tab1 行内锁 = 只锁渠道；Tab3 改名为「改名覆盖」，只有需要把对外名指向渠道里另一个模型名时才用它。
- **几处避让**：被改名绑定 / 别名 / 自定义接管的行不给锁（它们的渠道另有来源，硬锁会改错上游名，悬停可看原因）；单源模型不给锁（强制走所属渠道，锁了也没意义）；只有多渠道模型才出现可选渠道。
- **锁是「尽力锁」**：锁定的渠道被关闭 / 无可用账号时，请求回落自动路由，不会一失败就整模型 503（与 v1.82.2 体验一致）；锁值仍保留，界面如实提示「锁定已失效，可重新选择或改回自动」。
- **筛选与统计跟上**：来源筛选新增「渠道锁」，按锁值判定——锁已失效、行回落成渠道来源的模型也能被筛出来；Tab3 底部计数补「渠道锁 N」。
- **大小写收敛**：`Kimi-K3` 与 `kimi-k3` 只保留一条锁，不会落成两条互相打架（写锁时统一大小写，读锁时精确优先、回落不敏感匹配）。

## 升级即迁移：旧版反代网关锁好的渠道自动搬过来

- 从 v1.82.2 及更早升级上来的，旧的 `proxy.modelOverrides`（「渠道覆盖」表）本版**一次性**搬进本地网关的 `channelLocks`，并在配置里落标记——只搬一次，之后你在 Tab1 里清空锁定，不会被下次启动重新灌回来。
- 两表互不干扰：改名覆盖（`overrides`）与渠道锁（`channelLocks`）各自独立，存量 `overrides` 一个字节都不用动。
- 迁移挂在配置读取入口上（桌面 / Docker headless / Web 控制台三条形态都走同一处），不用为每种形态单独初始化；进程内只检查一次，不在请求热路径上反复扫旧表；写盘失败不阻塞读，下次启动重试。

## 修复（本轮纯静态审查发现）

本次对最近的全部改动做了一遍逐文件的静态审查，发现并修掉了一批「接线即崩」的问题，其中本地网关模块在接线前处于不可用状态：

- **本地网关**：`aggregateOpenaiEvents` / `aggregatedUsage` 两个函数只有调用没有定义（每次请求必然抛错）；转发时凭据取的字段与号池存储层签名不匹配（每次转发都以「凭据缺失」失败）；API Key 的 HMAC 密钥取自一个并不存在的接口，实际退化成硬编码常量；`handleMessages` 重复定义，生效的那份会把 SSE 帧写进非流式响应体。
- **本地网关**：并发闸门在异常路径上永久泄漏（连续失败十几次后整个网关永久 429）；路由的 score 策略恒为 0（取了一个不存在的字段），轮询 / 智能两个分支从未实现；并发闸门与超时未映射 504、流式失败被静默截断；`markSucceeded` 定义了却从未被调用，导致退避只增不减。
- **本地网关**：`x-api-key` 头声称兼容但实际没读（Claude Code 必 401）；admin / readonly 令牌用普通相等比较，且 readonly 令牌可以发起消耗额度的写请求。
- **本地网关**：SSE 实际是「先攒满再回放」，不是真流式；请求体大小上限因单位换算写成 `NaN` 而完全失效；客户端断开后请求 Promise 永不结束。
- **本地网关**：模块配置的 `patch` 会把整份配置写回，读不到完整配置时有抹掉其它模块配置的风险。
- **第五板块的注册链**：框架配置的 `moduleOrder` 已知集合没有 `localgw`，后端归一化时会把该 key 静默剔除——**第五板块在左栏根本不显示**；前端 `orderedModules` 只按 `moduleOrder` 映射取模块，缺 key 时没有任何兜底。两处都已补齐对称兜底。
- **配置页模块排序**：列表渲染的是「可启停模块」子集，上下移 / 拖拽却用可视列表下标去交换 `moduleOrder`，两者长度不同会换错行（localgw 不在末位时整列错位）。
- **提示词库**：线上目录「检查更新」在分片下载失败时仍把远端索引落盘，导致版本号先跳新值、失败分片**永远补不回来**；若干处渲染期计算对缺字段的接口返回值没有兜底，会带崩整页。
- **自测运行时选择**：`run-all-tests` 原来按脚本源码里有没有 `node:sqlite` 字样挑运行时，漏判两类脚本（传递依赖数据库层、依赖全局 fetch），一次跑出 6 个假红把真实的护仓信号淹掉。改为优先用 Electron 自带 Node（应用真实运行的环境）；需要强制普通 node 时设 `TESTS_FORCE_NODE=1`。

# v1.87.1 更新说明

## 修复：更新安装「应用退出后新版本没装上、也没自动重启」

- **问题**：点击「立即重启安装」或退出时自动安装后，应用退出、但新版本没有装上、也没有自动重启，且没有任何报错。根因是安装器启动此前交给 electron-updater 的内部实现——它发出启动指令后立即退出应用，一旦安装器启动失败（杀毒软件对刚下载安装包的实时扫描锁、文件占用等），错误信息随应用进程一起丢失，无从排查。
- **修复**：安装器启动改为自己接管——启动前先整包校验 sha512 并读盘预热（化解杀软扫描锁）；启动失败自动重试（1.5 秒间隔最多 3 次），仍失败回退提权方式拉起；任何一步失败应用**都不再退出**，更新中心会显示明确原因，可直接重试。更新组件的内部日志也会记入 `logs/crash.log`，后续更新问题可精确定位。

# v1.87.0 更新说明

本版新增第五大板块「提示词库」：一个本机优先、可跨设备同步的提示词资产库，外加一个对标「增强提示词」的优化工作台。同时带来外置插件的桥接与内嵌界面、以及无边框自绘标题栏。

## 提示词库（第五大板块）

- **优化提示词**：上方输入原文、中间按钮、下方出结果。可选优化风格（内置 5 套：通用增强 / 更简洁 / 更结构化 / 补全约束 / 面向编码任务）、选模型，并可调长度上限、温度、最大输出、超时与目标场景；结果可一键复制、重新优化、保存到库、与原文并排对比。
- **个人提示词库**：两级分类与标签、全文搜索、收藏、卡片/列表视图、批量操作与回收站；每条都有版本历史与血缘（记录从哪条原文、哪个风格、哪个模型生成）。
- **优化历史**：最近 50 次记录（失败的也留痕并写明原因），可回填、复制、删除。
- **复用平台模型**：优化直接走「设置 · 模型与网关」里已配置的供应商与模型池，沿用降级链、失败重试与用量记账，不需要额外配置。

## 跨设备同步（独立链路）

- 与技能仓库 / 用量统计 / 号池管家 / 记忆中枢**各自独立**、互不阻塞，在「设置 · WebDAV 同步」里有自己的根目录。
- **冲突默认自动合并**（默认新者优先），被放弃的那一份会写入该条目的版本历史，可在同步页逐条查看并改判；也支持一键「自动合并全部」，或改为全部人工裁决。
- 同步周期在「设置 · 同步时间 → 提示词库」按小时设置，默认每 4 小时，默认开启。
- 回收站删除以墓碑方式同步，不会在别的设备上「复活」；远端清单异常为空时会停下来而不是覆盖。

## 外置插件与窗口

- 插件可声明桥接资源与内嵌界面地址，界面直接嵌入主区域（CSP 仅放行本机回环地址）。
- 无边框窗口 + 自绘标题栏：版本 / 作者 / Star / 主题 / 设置，以及最小化 / 全屏 / 关闭。

## 升级提示

- 覆盖安装即可。本版不改动既有四大板块的数据与配置；提示词库默认库目录为 `~/AgentHub/prompts`，首次使用会自动创建，本机偏好（优化风格与历史）另存于用户数据目录，不参与同步。

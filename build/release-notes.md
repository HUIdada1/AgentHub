## 修复：商汤渠道「HTTP 400」相关的两条自家必拒路径 + 失败提示与留证

- 「思考强度 = 关」时会给 GLM 系模型（`glm-5-3` 等）发上游不认的 `reasoning_effort:"off"`，而这条链路只接受 `low / high / max`——**必然 400**。现在「关」按官方语义译成 `low`（仍是关思考），并避免发上游不认的 `thinking` 字段；其它模型家族的请求体一个字节都不动
- 上游在「渠道校验阶段」按客户端身份拒绝（400）原先被当成请求参数错：直接失败、**不跳备选渠道**，还会把无辜账号罚 60 秒冷却并在号池卡片挂一条误导性错误。现在这类拒绝会跳过当前渠道走备选、不罚账号；真参数类 400 语义完全不变（仍原样透传，不会被拿去白绕一圈多烧额度）
- 失败提示与留证补齐：客户端错误消息带 `[ah:xxxxxxxx]` 请求 id（投诉时可直接引用）；记账里保留上游的 `request_id` / `code`（此前 200 字截断会把 request_id 切掉）；上游返回 200 但一个 token 都没产出的行会标注 `notice:empty-completion`
- 「反向映射」不再收窄备选渠道：给某模型配了反向映射后，跨渠道自救的备选集合原会缩成映射里写的那几个渠道；现在映射里的渠道排最前、其后仍带上目录里拥有该模型的其它渠道

## 说明

- 上游按客户端指纹在渠道校验阶段拒绝属于**上游策略**，AgentHub 无法根除；本次修的是它带来的连带伤害（自家必 400 的参数形态、不跳备选、误罚账号、证据丢失）
- 不启用「注入受支持客户端身份」的规避手段：有效性未证实，且涉及伪装客户端身份，需单独决策
- 自测扩展：小浣熊思考参数归一（GLM 归一、非 GLM 逐字节不变）、故障转移的身份拒绝自救与真参数 400 不放宽、反向映射后备选完整性；既有成本路由、空池路由、共享同步各套无回归

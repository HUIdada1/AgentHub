# v1.83.0 更新说明

本版停止维护「反代网关」，模块改造为「号池管家」：**保留号池账号、余额、积分签到、跨设备同步与操作日志，移除 API 转发能力**。

## 号池管家（原反代网关）

- **模块更名**：左侧导航与设置里的「反代网关」统一改为「号池管家」。
- **页面收敛为五个**：总览 / 号池 / 积分日历 / 号池同步 / 日志。API Keys、模型目录、用量统计、自定义提供商、生态接入、网络代理六个页面随转发能力下线。
- **总览重写**：不再有服务开关、接入地址与实时请求流，改成各渠道余额卡片（可用账号数、最早到期、今日请求与 Token，支持单渠道刷新余额）+ 四个号池指标 + 最近动态。
- **配置页精简**：只留额度监控（「即将到期」阈值、余额历史保留期、自动刷新与定时签到引导）与凭证数据（DPAPI 状态、数据目录），保存不再重启任何监听。
- **号池能力不变**：加号（OAuth / 本机导入 / JSON·ZIP 文件 / 粘贴）、余额刷新、签到与自动签到、切到本机 IDE、上游启闭、号池同步、日志导出全部保留。

## 已下线

API 转发服务（OpenAI / Anthropic / Responses 三条协议面）、API Keys、模型目录、网关用量统计、自定义提供商（中转站）、CC Switch 生态接入、网络代理（出口池）、Docker 版与远程实例、规则热加载。

相关代码已归档到仓库内的 `废弃代码（禁止git提交推送）/` 目录（该目录已在 `.gitignore` 中整体忽略，不参与提交与推送），原 Docker 形态网关的 CI 一并移除，替换为只覆盖保留能力的 `Pool CI`。

## 维护策略调整

「反代网关」转入停止维护状态：不再做功能开发与代码更新，不再跟进各渠道上游的协议调整与风控策略变化，也不再受理相关新增 issue 与 PR。本项目为个人自用工具，不具备长期投入协议适配与风控对抗的能力；受上游策略更新频率影响，反代通道的稳定性与可用周期已不可控。仓库保持现有可用状态，已合入的修复不作回退。

## 说明

- **升级后网关服务不再启动**：原来填了网关地址（`http://127.0.0.1:9527/v1`）的客户端会连不上，请改回官方接口或自建端点；已生成的 API Key 不再可用。
- **账号与历史数据保留**：号池账号、余额历史、操作日志都在原数据目录里，无需迁移；记忆中枢的「本机网关」档改为「自建 OpenAI 兼容端点」语义，未填地址时自动跳过。
- 敬请自行评估使用风险：受上游策略影响，余额查询与签到存在随时不可用的可能；因使用非官方客户端产生的账号风控、限制或封禁等后果，由使用者自行承担。

# v1.82.2 更新说明

# v1.80.0 更新说明

本版给反代网关加了一层「同 body 去重排队」：客户端快速重试时，相同请求不再同时打到上游，而是排队串行发；流中空闲超时也单独归类，慢请求不再误伤账号。AutoClaw 渠道补了 CodeBuddy CLI 与 Trae SOLO 的身份句改写。

## 反代网关 · 调度

- **同 body 请求去重排队**：客户端超时后立刻重试时，同一个 body 的第 2、3 个请求会等第 1 个结束再发（等待上限 45 秒，到点无条件放行）。槽位持到流式正文下发完毕才释放，避免「重试请求」与「仍在输出的上一个请求」并发打到上游。可在「配置 · 反代网关」用 `dedupeSameBody` 关闭、`dedupeWaitMs` 调整等待上限。
- **慢请求不再罚号**：流中空闲超时单独归类为 `slow`（HTTP 504），不再计入服务端错误档位——原来连续 3 次会熔断账号 30 分钟，现在只影响本次请求。
- **429 同号重试延迟可调**：新增 `rateRetryDelayMs`（默认 1000ms），实际延迟带 ±15% 抖动，多账号同时醒来时不会形成惊群。
- **尝试明细进日志**：一次请求尝试 2 次以上时，`op_logs.detail` 会记下 `渠道/账号:结果(耗时) → …` 的完整链路，排障不用再靠猜。
- **内容过滤单独标注**：上游返回 HTTP 200 但 `finish_reason=content_filter` 时，记一条 `notice:content-filter`，不再当成正常成功。

## 反代网关 · AutoClaw

- **补 CodeBuddy CLI / Trae SOLO 身份句改写**：这两个客户端的 system 身份句不在改写表内，前置身份前缀后指纹残留，被上游拦成 406 空响应体。新增三条改写（长的在前、替换串不含产品名），并补 5 条断言。感谢 @lin-code-world 的 PR #160。

# v1.79.1 更新说明

本版修 WorkBuddy 国际版免费模型的 429/6004 处理：不再把「账号×模型的频率上限」误读成额度耗尽，冷却按上游真实重置时间执行，避免反复重试和旧错误长期挂在号池卡片上。

## 反代网关 · WorkBuddy 国际版

- **6004 重置时间解析补全**：上游英文文案（`your usage will reset at ... UTC+8`）此前解析不到，冷却只能落 10 分钟兜底——真实重置还早时会每 10 分钟重试一次、看起来像额度永久用完；真实重置只剩几分钟时又比上游多关一段。现在正文里的日期时间（中英文都认）和 `Retry-After` 都会用于对齐真实重置时刻。
- **6004 不再写账号「最近错误」**：6004 只罚「账号×模型」，错误原因仍保留在模型级冷却的悬浮明细里；不再落到账号卡片，避免冷却/重置结束后仍挂着旧 429。号池卡片另外只把「上次成功调用之后」的错误标红，历史错误不再误导。
- **对话端点对齐官方客户端**：国际版优先走 `/v2/chat/completions`（本机 5.8.4 官方桌面客户端实际路径），`/console` 仅作 404/405 兜底；避免两条入口限频口径不一致带来的额外 6004。
- **流内 6004 正确归 429**：上游在 SSE 里返回 6004 时不再被当成 502 服务故障，客户端会按限频处理而不是立刻重试。
- **每日活跃保活让出 DeepSeek 免费窗口**：保活模型链改为优先 `hy3`/`hy4-preview`，`deepseek-v4.1-flash` 放最后，减少与真实对话抢同一个账号×模型额度。

## 说明

本版给 WorkBuddy 国际版补上「每日活跃」保活三件事，修了 Trae 渠道的错误分类与目录过滤、Qoder 排队等待的无效重试，并把用量统计总览的加载从近 0.8 秒提到瞬时。

## 反代网关 · WorkBuddy 国际版

- **每日活跃保活（新功能）**：国际版上游没有「每日签到」体系，每日奖励的活跃判定挂在三条通道上，缺一条就领不到。本版在「签到」时把三件事一次做齐：① 活跃上报（点亮成长中心连登）；② 用免费模型发一次最小对话（保持账号有调用，不耗积分）；③ 网页通道建一个会话（每日活跃计数只认它）。
- 三件事都是尽力而为：任一步失败只显示失败原因，绝不影响加油包/签到的结论；仅国际版触发，国内版不发多余请求。
- 网页通道的请求剥掉桌面端指纹、只带必要凭据，会话体与浏览器端形态一致。

## 反代网关 · Trae 渠道

- **模型目录过滤三类非可选条目**：内部 subagent、租户自定义模型的占位模板、已下线开关不再混进模型目录；判据一律「缺省可见」，上游删字段时不会把整张表误滤空。
- **「模型不可用」错误改报 404**：上游 4001 表示该模型在当前通道不可用（不是服务故障），此前报 502 会让客户端以为上游挂了、反复重试同一个必死的模型；改 404 后客户端会直接换模型，账号不受罚。
- **「输入过大」独立成一档**：一次超长输入不再被当成账号错误——此前这类请求会顺着换号链把整池账号逐个罚掉，现在按 413 原样透传、零动作、不罚号。

## 反代网关 · Qoder 渠道

- **排队不再 1 秒白撞**：上游 10605 排队错误的正文里带着建议等待时长（实测 9~30 秒），此前不带时长只退 1 秒就重打，高峰期每个号都要白撞一遍。现在按上游建议落冷却并直接换号；上游没给时长时不猜值，行为与之前一致。

## 用量统计

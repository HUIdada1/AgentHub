# 远程访问管理控制台（四档，按风险从低到高）

先说一件最容易让人以为"配坏了"的事 ↓

## 前置事实：没设 token 时容器**照样启动**，只是控制台打不开

管理面的行为是一张四态表（实现见 `gateway/src/index.cjs` 的 `isNonLoopbackHost` 与安全闸段，
逐行解释在 `../gateway/README.md`「安全闸」一节）：

| 令牌 | `AGENTHUB_ADMIN_PUBLIC` | 结果 |
| --- | --- | --- |
| 无 | `0.0.0.0` / `1` / `true`（显式要公网） | **拒绝启动**，日志给一行修法 |
| 无 | 默认 / `127.0.0.1` | **正常启动**，但管理面被强制降回**容器内回环** + WARN |
| 有 | 默认 / `127.0.0.1` | 容器内 `0.0.0.0`、宿主只回环可达（**推荐态**） |
| 有 | `0.0.0.0` | 全公网可达 + WARN 建议前置 TLS 反代 |

所以：**第 ② 态不是故障**。容器健康检查（在容器内 curl 回环）仍绿、`/v1` 网关照常对外服务，
只有浏览器打不开 `http://<主机>:19528/`。`docker logs` 里能看到那行
「未设 AGENTHUB_ADMIN_TOKEN → 管理面已从 0.0.0.0 强制降回 127.0.0.1（容器回环）」。
降级后的行为与这个安全闸上线**之前**完全一致（容器内绑回环时宿主 DNAT 本就转不进来），
所以老部署升级不会被破坏 —— 这是刻意的选择：宁可你打不开，也不让全权管理面无鉴权裸奔。

要远程访问，先把 `AGENTHUB_ADMIN_TOKEN` 设上，再从下面挑一档。

---

## A 档 · SSH 隧道（应急/排障，零暴露）

适合：先验功能、临时改一个配置，不想在任何地方开端口。

```bash
ssh -L 19528:127.0.0.1:19528 <你登录那台宿主机用的用户>@<宿主机>
# 然后本机浏览器打开
http://127.0.0.1:19528/
```

- `compose.yml` 保持默认（`AGENTHUB_ADMIN_PUBLIC` 不设），宿主上管理面本来就只绑 `127.0.0.1`，
  隧道把它当本机端口用，公网侧**一个口子都不多开**。
- 群晖 DSM 默认不跑 sshd 的端口转发策略时也能用（要先在 控制面板 → 终端机 里启用 SSH）。
- 缺点：每次都要开隧道，手机不方便。

## B 档 · 前置带 TLS 的反向代理（**推荐给公网部署**）

思路：容器里管理面仍只绑宿主回环（`PUBLIC` 保持默认），由宿主机上的 **Caddy/Nginx** 出面
做 HTTPS + 访问日志 + 认证前置。样例见 [`caddy/Caddyfile`](caddy/Caddyfile)（含自动证书）。

三条硬要求，少一条就会出"看起来能打开但用不了"：

1. **SSE 不能缓冲**。控制台的事件流是 `GET /api/events`，代理若缓冲，进度条不动、
   用量页不刷新。Caddy 用 `flush_interval -1`；Nginx 用 `proxy_buffering off;` +
   `proxy_read_timeout 3600s;`。
2. **请求体上限要对齐**。网关侧全局 JSON body 限 `4mb`（`index.cjs:191`），插件包上传**不走**
   这条限制 —— 它是流式落盘、上限 200MB（`index.cjs:664`，与 `plugin-host.cjs:35` 同口径，
   边写边计数、超限立刻断，避免 512M/1G 的 cgroup 被一次上传挤爆）。
   但反代层通常自带 body 上限（Nginx 默认 `client_max_body_size 1m`），
   不放开的话上传会在反代处 413，而网关日志里一个字都不会留。
3. **`/api` 与静态资源同源**：直接把整个 host 反代到 `127.0.0.1:19528` 最省事，
   别只反代 `/api` —— Web 控制台的产物是相对路径，拆开会 404。

登录机制要知道的一件事：控制台的令牌存在浏览器 `localStorage`，请求以
`Authorization: Bearer <token>` 发出；收到 401 会清令牌并刷新页面。所以
**换了 `AGENTHUB_ADMIN_TOKEN` 后，浏览器要重新登录一次**（旧令牌立刻失效）。

## B′ 档 · 单端口同源（最终形态，但**需要你自己确认是否要做**）

把管理面与网关收敛成一个对外端口，反代更简单、证书更少、CSP 天然满足。
现状是管理面与 `/v1` 网关分占 19528 / 19527 两个端口（`gateway/Dockerfile` 的 `EXPOSE`）。
要合成一个端口需要改绑定语义，风险偏高，本板块**没有做**；`compose.yml` 里
`AGENTHUB_ADMIN_PUBLIC` 这个开关就是为"先不动绑定、但要能公开"准备的过渡形态：

```bash
# deploy/.env
AGENTHUB_ADMIN_TOKEN=<必填，否则这一档直接拒启动>
AGENTHUB_ADMIN_PUBLIC=0.0.0.0        # 宿主侧发布到所有网卡
```

这样不做任何反代就能从外网打开控制台。**代价**：密码在公网上被爆破的面敞开了，
所以：
- 令牌强度请当成 SSH 密码来选（不是"好记即可"了）；
- 只读令牌（`AGENTHUB_ADMIN_READONLY_TOKEN`）适合"给家人/看板看，不给他改"的场景；
- 认证失败目前**没有限速**（已列在整改方案的安全项里），所以裸端口长期暴露不建议。

## C 档 · 群晖 Container Manager + DSM 自带反向代理

图形化步骤见 [`nas-群晖.md`](nas-群晖.md)。要点两条：
1. 端口映射填 `19528`，**勾上"仅本地访问 / localhost"**（等价于 `PUBLIC=127.0.0.1`）；
2. DSM 反向代理规则里把 **WebSocket / SSE 缓冲关掉**（"启用 HTTP/2" 与 "Websocket" 勾上，
   高级控制里自定义 `proxy_buffering off`），否则事件流会被挂住。

## 选哪一档

| 场景 | 建议 |
| --- | --- |
| 只在同局域网用（NAS 家用） | 默认 `PUBLIC=127.0.0.1` + A 档隧道；嫌麻烦就 B′ + 强密码 + 路由器只放内网 |
| 有域名、要公网访问（如 `bigkun.lol`） | **B 档**：Caddy 自动 HTTPS，`PUBLIC` 保持 127.0.0.1 |
| 临时排障 / 第一次装完验功能 | A 档 |
| 群晖且不想装额外软件 | C 档 |

## 数据面（`/v1`）与管理的区别，别搞混

- `19527/v1` 是**给客户端连的模型网关**，它的凭据是你创建的 **API Key**（形如 `sk-lgw-…`，
  库里只存前 12 位前缀、不存明文），与管理令牌**是两套东西**；该端口必须无前缀映射到宿主网络，
  否则外部客户端连不上。
- `19528` 是**管理面**（Web 控制台 + REST），用管理令牌。默认只绑宿主回环。
- 只给外部客户端用、不需要远程管理时：**什么都别改**，默认就是安全的那一档。

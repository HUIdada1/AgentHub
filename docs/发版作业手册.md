# AgentHub 发版作业手册（SOP）

> 执行约定：任何会话中对本项目说「发版」，即按本手册全流程操作，不得跳步。
> 参考实现源自 `E:\idea work\用量记录同步\docs\发版作业手册.md`（Dosage Sync，已验证跑通多版）。

## 一、发布链路总览

```
改代码 → 升版本号 → 本地构建验证 → git 提交 → 推送 GitHub main
  → GitHub Actions Release 流水线（workflow_dispatch 手动触发）
  → 自动构建并创建 Release（tag + 安装包 + 便携版 + latest.yml + blockmap）
  → 验证发布结果 → 补 Release 更新说明
  → 客户端：安装版自动检测更新（启动 60 秒后首次，之后每 6 小时）；便携版提示手动下载
```

推送与发版地址（同一个仓库）：

- 仓库：https://github.com/HUIdada1/AgentHub.git
- 发版资产：https://github.com/HUIdada1/AgentHub/releases

## 二、前置条件（每次发版前确认）

| 项 | 要求 | 检查命令 |
|---|---|---|
| 工作区 | 干净、位于 main 分支 | `git status` |
| GitHub 代理 | Clash 等代理在线（7897 端口） | `git config --global --get http.proxy` |
| 版本号 | 严格高于 GitHub 当前最新 tag（tag 一旦发布永久占用，不可复用） | `git ls-remote --tags origin` |

## 三、发版步骤

### 1. 升版本号

编辑 `package.json` 的 `version`。语义：bug 修复升补丁位，新功能升次位，破坏性变更升主位。

### 2. 本地构建验证

```bash
npm run build            # vue-tsc 类型检查 + vite 构建（类型错误必须在此拦截）
npm run electron:pack    # 可选：只打包到 release/ 做本机验证，不发 Release
```

### 3. 提交

commit message 遵循项目风格（中文、feat/fix/chore 前缀、说清改动与影响面）：

```bash
git add -A
git commit -m "feat: 改动说明"
```

### 4. 推送 GitHub

```bash
git push origin main
```

```bash
git config user.name "HUIdada1"
git config user.email "HUIdada1@users.noreply.github.com"
```

若日后新增阿里云 Codeup 私有镜像仓（放 `docs/` 等不便公开的内容），改用参考项目的
「双推 + GitHub 孤儿快照」方案：Codeup 保留完整历史，GitHub 侧每次用中性作者重建单提交快照并
force-push，`docs/` 与 `tools/.audit-*` 通过 pathspec 排除并加泄漏断言。

### 5. 触发发布流水线

GitHub Actions 用 `workflow_dispatch` 手动触发（**不用 tag 触发**：tag 由 electron-builder 在发布时自动创建）。

网页操作：仓库 → Actions → Release → Run workflow（版本号留空则用 `package.json` 的）。

API 方式（Git Bash）：

```bash
PAT=<你的 GitHub PAT>
curl -sS -X POST \
  -H "Authorization: Bearer $PAT" -H "Accept: application/vnd.github+json" \
  -H "X-GitHub-Api-Version: 2022-11-28" \
  https://api.github.com/repos/HUIdada1/AgentHub/actions/workflows/release.yml/dispatches \
  -d '{"ref":"main","inputs":{"version":"0.1.1"}}' -o /dev/null -w "HTTP %{http_code}\n"
# 期望 HTTP 204
```

流水线内置门禁（任一失败即中止）：输入版本与 `package.json` 一致且严格高于 GitHub 最新 tag、
并发保护（同时间只跑一个）、vue-tsc 类型检查、发布后校验 latest.yml 可下载。

### 6. 轮询流水线结果（构建约 3~6 分钟）

```bash
curl -sS -H "Authorization: Bearer $PAT" -H "Accept: application/vnd.github+json" \
  "https://api.github.com/repos/HUIdada1/AgentHub/actions/runs?branch=main&per_page=1"
# status=completed 且 conclusion=success 即成功；failure 看流水线日志
```

### 7. 验证发布结果（全部通过才算完成）

- Release 状态为正式发布（`draft:false`），资产四件齐全：`AgentHub-Setup-x.y.z.exe`、
  `AgentHub-x.y.z-portable.exe`、对应 `.blockmap`、`latest.yml`。
- `latest.yml` 直链版本号匹配（安装版 / 便携版客户端都依赖它）：

```bash
curl -sSL "https://github.com/HUIdada1/AgentHub/releases/latest/download/latest.yml" | head -1
# 期望 version: 新版本号（草稿转正路径下 latest 路由有约 1 分钟索引延迟，
#   此时改用带版本号直链 releases/download/vX.Y.Z/latest.yml 立即验证）
```

### 8. 补 Release 更新说明

CI 创建的 Release body 默认是空，用户端设置页会把 body 当更新日志展示，必须补。
body 用 Markdown 写即可（`##` 分节、`-` 列表）：客户端从 releases **atom feed** 取到的是 GitHub
渲染后的 HTML（`<h2>/<ul>/<li>`），由 `electron/backend/updater.cjs` 的 `htmlToText()` 还原成
「标题 + · 列表项」的纯文本再展示。**不要往 body 里写 HTML 标签**（会被一并抹掉）。

```bash
# 用 tag 名查 release id，再 PATCH（不能用 /releases/latest 端点写）：
curl -sS -X PATCH \
  -H "Authorization: Bearer $PAT" -H "Accept: application/vnd.github+json" \
  -H "Content-Type: application/json" \
  "https://api.github.com/repos/HUIdada1/AgentHub/releases/<release_id>" \
  -d @notes.json    # notes.json: {"body":"## 新功能\n- ...\n\n## 说明\n- ..."}
```

## 四、客户端热更新机制（改动前必读）

实现集中在 `electron/backend/updater.cjs`，接线在 `electron/main.cjs` 与 `electron/backend/ipc.cjs`。

- **安装版**：electron-updater 拉取 latest.yml；启动 60 秒后首次检查 + 每 6 小时一次；
  设置页「软件更新」卡片可手动检查 / 下载 / 重启安装；退出应用时已下载的更新静默安装
  （`main.cjs` 的 before-quit 钩子，`/S --force-run`）。下载与安装均由用户触发
  （`autoDownload=false`、`autoInstallOnAppQuit=false`）。
- **便携版**：仅用 Electron net 模块（走系统代理）读 latest.yml 直链比对版本，检测到新版提示到
  GitHub 手动下载，不自动更新。便携版判定见 `config.cjs` 的 `isPortable()`
  （优先读 portable stub 注入的 `PORTABLE_EXECUTABLE_DIR`）。
- 自动检查开关持久化在 `config.json` 的 `update.autoCheck`，设置页改动即时生效
  （每轮检查前读盘）。
- 通知去重持久化在 `config.json` 的 `update.notifiedVersion`（同版本跨会话只提醒一次；
  触发安装时清空以便失败后重新提醒）。该字段由主进程维护，`save_config` 会以磁盘值为准覆盖
  渲染层传来的旧快照。
- 更新说明来自 releases atom feed 的 `<content>`（**HTML，非 Markdown**），由 `updater.cjs` 的
  `toNotes()/htmlToText()` 转纯文本后展示，展示区限高内滚。
- 任何改动 `release.yml` / `updater.cjs` / 版本口径前，先读 `electron/backend/updater.cjs` 全部注释。

## 五、故障排查表

| 现象 | 处理 |
|---|---|
| Actions 报「版本必须严格高于最新 tag」 | 版本号没升或低于已发布版本；tag 永久占用，改更高版本号重来 |
| 发布的 Release 是 draft、latest.yml 404 | 检查 `package.json` 的 `build.publish[].releaseType` 是否为 `"release"`；旧版本可手动 PATCH `draft:false` 转正（转正后 latest 路由延迟约 1 分钟） |
| 输入版本与 package.json 不一致 | 流水线直接失败，改输入或改 package.json 后重新触发 |
| CI 下载 Electron 二进制失败 | `.npmrc` 的 npmmirror 镜像可能未同步该版本，先等几分钟；严重时临时移除镜像重试 |
| 客户端不提示更新 | 确认 Release 非 draft、latest.yml 可下载、本机版本低于 latest.yml；便携版看设置页提示 |
| 更新说明显示成一堆尖括号标签 | Release body 里写了 HTML，或 `htmlToText` 被改动；body 只写 Markdown |
| 发布失败无 tag | 修好后重新触发即可（tag 是发布成功的判据，失败不占版本号） |
